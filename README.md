# Altium Vibe-EE MCP

An MCP (Model Context Protocol) server that gives LLM agents (Claude, Cursor, GPT, ...) structured,
read-only access to a **running Altium Designer**: workspace, open projects, sheet hierarchy,
compiled components, nets, pins, parameters and compile violations.

Phase 1 (this repo today) is read/analysis: compiled project model, schematic sheet object model and PCB
board object model. The architecture is built so that later phases can add Workspace-aware collaboration,
schematic/PCB edits, verification loops and an agent harness on top. Target EDA is Altium Designer only.
See `docs/ROADMAP.md`.

```
MCP client (Claude Desktop / Cursor / Claude Code)
   │ stdio (JSON-RPC, MCP)
   ▼
AltiumMcp.Server.exe          ← out-of-process .NET 8 console, 22 tools
   │ HTTP JSON-RPC on 127.0.0.1:47120   (discovery: %LOCALAPPDATA%\AltiumMcp\bridge.json)
   ▼
AltiumExtensionMCP.dll        ← .NET 8 Altium extension loaded inside X2.EXE
   │ Altium SDK (COM), marshalled to the UI thread
   ▼
Altium Designer 26 (workspace manager, compiled project model, SCH + PCB object models)
```

## Requirements

- Windows, Altium Designer 26.x (verified: 26.3.0 and 26.9.1) with the *Altium Developer* extension
  (SDK25: `Altium.SDK.dll`; `Altium.SDK.Interfaces.dll` ships in Altium's `System` folder).
- .NET SDK 8 or newer (built with 10.0.x; targets net8.0 because AD26 hosts .NET 8).
- All machine-specific paths (Altium install, profile GUID, SDK, deploy folder, test projects) are
  resolved from `Environment.local.props`, generated by `tools\Detect-AltiumEnvironment.ps1`.
  Current values and the migration checklist: **`docs/ENVIRONMENT.md`**.

## Build

```powershell
git clone <this repo> <ProjectRoot>
cd <ProjectRoot>
powershell -File tools\Detect-AltiumEnvironment.ps1 -CopyExamples   # once per machine: writes Environment.local.props
dotnet build AltiumMcp.slnx -c Debug            # builds + deploys the extension to Altium
dotnet test  AltiumMcp.slnx                      # 27 unit tests (no Altium needed)
```

`dotnet build` of `AltiumMcp.Extension` copies the extension into the Altium profile's
`Extensions\AltiumExtensionMCP\` folder (`<ExtensionDeployDir>` in `docs/ENVIRONMENT.md`).
**Altium must be closed** during that copy (it locks the DLL once loaded). To build without deploying:
`dotnet build -p:DeployToAltium=false`. Without `Environment.local.props` the extension build fails
with a hint; Contracts/Server/Tests build and test on any machine.

## Install / load the extension in Altium

First time on a machine: register the extension in the profile's `ExtensionsRegistry.xml`
(`powershell -File tools\Register-Extension.ps1`, Altium closed). Altium loads extension DLLs lazily.
Two reliable ways to load ours:

1. **Command-line switch at startup (recommended, scriptable):**
   ```powershell
   & "<AltiumExe>" -RAltiumExtensionMCP:StartBridge
   ```
   The bridge is up ~5 s after launch, before the main window finishes loading.
   `tools\Start-AltiumWithBridge.ps1 [-Restart] [-Project <.PrjPcb>]` wraps this and waits for the bridge.
2. **Already-running Altium:** *File > MCP Bridge > Start* (home page) / *Tools > MCP Bridge* (SCH/PCB
   editors) or *DXP > Run Process* → `AltiumExtensionMCP:StartBridge` (`:ShowBridgePanel` also opens the
   *MCP Bridge* status panel). Loading the module starts the bridge. A plain restart of Altium does
   **not** reload the extension by itself — use the `-R` switch or the helper script.

Full dev loop (close Altium → build+deploy → register if needed → start with bridge → open the test
project): `powershell -File tools\Redeploy-Extension.ps1`.

Verify:

```powershell
src\AltiumMcp.Server\bin\Debug\net8.0\AltiumMcp.Server.exe --health
src\AltiumMcp.Server\bin\Debug\net8.0\AltiumMcp.Server.exe --call workspace.getInfo
```

## Connect an MCP client

Claude Desktop (`%APPDATA%\Claude\claude_desktop_config.json`) / Cursor (`.cursor\mcp.json`) /
Claude Code (`claude mcp add ...`) — point `command` at the built server exe (`<McpServerExe>` in
`docs/ENVIRONMENT.md`):

```json
{
  "mcpServers": {
    "altium": {
      "command": "<ProjectRoot>\\src\\AltiumMcp.Server\\bin\\Debug\\net8.0\\AltiumMcp.Server.exe"
    }
  }
}
```

Optional environment: `ALTIUM_MCP_BRIDGE_URL` (full base URL) or `ALTIUM_MCP_BRIDGE_PORT` to
override discovery (needed only when running several Altium instances with bridges).

Then give the agent the skill `skills/altium-project-analysis/SKILL.md` (copy it into your
client's skills folder) and ask, e.g. *"Which ICs are on the open project and what nets does U1's
power pins connect to?"*

## Minimal working example

With Altium running and a `.PrjPcb` open (`tools\Invoke-Bridge.ps1` avoids PowerShell JSON quoting;
the raw CLI also accepts `--call <method> @params.json` or `-` for stdin):

```powershell
. .\tools\Invoke-Bridge.ps1
Invoke-Bridge system.ping
Invoke-Bridge workspace.listProjects
Invoke-Bridge project.getStructure
Invoke-Bridge project.listComponents @{ filter = 'U*'; limit = 10 }
Invoke-Bridge project.getComponent   @{ component = 'U1' }
Invoke-Bridge project.listNets       @{ filter = 'VDD*' }
Invoke-Bridge project.getNet         @{ net = 'GND' }
$prj = Get-TestProjectDir                      # <TestProjectsRoot>\Bluetooth Sentinel
Invoke-Bridge sch.listObjects @{ documentPath = "$prj\Bluetooth_Sentinel.SchDoc"; types = @('SheetSymbol','Port') }
Invoke-Bridge pcb.getBoard    @{ documentPath = "$prj\Bluetooth_Sentinel.PcbDoc" }
Invoke-Bridge pcb.getNet      @{ documentPath = "$prj\Bluetooth_Sentinel.PcbDoc"; net = 'GND' }
```

Tested against the Altium example *Bluetooth Sentinel* (72 components, 65 nets, 15 sheets):
project calls return in < 30 ms after the first compile; PCB calls ~1 s on a hidden-loaded board.

## Tools (MCP names)

- Connection: `altium_ping`, `altium_get_environment`, `altium_bridge_diagnostics`
- Workspace: `altium_get_workspace`, `altium_list_projects`, `altium_list_open_documents`, `altium_open_document`
- Project (compiled model): `altium_get_project_structure`, `altium_list_components`, `altium_get_component`,
  `altium_list_nets`, `altium_get_net`
- Schematic (sheet object model): `altium_get_sheet`, `altium_list_sheet_objects`, `altium_get_sheet_component`
- PCB (board object model): `altium_get_board`, `altium_list_pcb_components`, `altium_get_pcb_component`,
  `altium_list_pcb_nets`, `altium_get_pcb_net`, `altium_list_pcb_rules`, `altium_list_pcb_primitives`

Details, inputs/outputs and verification status: `docs/MCP_TOOLS.md`.

## Troubleshooting

| Symptom | Cause / fix |
|---------|-------------|
| Extension build: "Altium SDK location unknown / not found" | Run `tools\Detect-AltiumEnvironment.ps1` (see `docs/ENVIRONMENT.md`) or build with `-p:DeployToAltium=false` for server/tests only. |
| `BRIDGE_UNAVAILABLE`, `altiumProcesses: []` | Altium not running. Start it with `-RAltiumExtensionMCP:StartBridge`. |
| `BRIDGE_UNAVAILABLE`, Altium running, no `bridge.json` / stale pid | Extension not loaded in this instance. `tools\Start-AltiumWithBridge.ps1 -Restart`, or start it from inside Altium (File > MCP Bridge > Start). Check `%LOCALAPPDATA%\AltiumMcp\logs\bridge-YYYYMMDD.log`. |
| `-R` switch starts nothing / no log line | Extension not registered in `ExtensionsRegistry.xml` on this profile: `tools\Register-Extension.ps1` (Altium closed). |
| `NOT_COMPILED` | Project has no compiled model: *Project > Validate PCB Project* in Altium, or pass `compileIfNeeded=true`. |
| Build error copying DLL | Altium is running and holds the DLL. Close it or build with `-p:DeployToAltium=false`. |
| Port 47120 busy | Bridge picks the next free port and writes it into `bridge.json`; the server follows the file. |

Logs: extension → `%LOCALAPPDATA%\AltiumMcp\logs\`; MCP server → stderr (stdout is the MCP transport).
